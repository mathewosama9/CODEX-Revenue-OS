## 2. الصورة الكبيرة للمراحل

```
P0a (من غير كود) → P0b (spikes + Audit) → [Gate 0: ≥5 دفعوا]
  → P1 استرجاع مُقاس → [Gate 1: تجديد مدفوع]
  → P2 AI Agent  ─┐   (أو إطلاق Recover الأول — قرار بعد P1)
  → P3 إطلاق عام على متجر سلة → [Gate 3 = الـMVP اتسيّل]
  → P4 / P5 / P6 = اتجاهات مشروطة بالطلب، مش خطة بناء
```

| Phase | الهدف في جملة | فيها كود؟ | المدة [افتراض] | البوابة اللي لازم تعدّيها |
|---|---|---|---|---|
| **P0a** | نختبر الدفع والمنصات والقانون قبل أي سطر | لأ | أسبوع 1–3 | — |
| **P0b** | spikes تقنية + Cart Truth Audit (read-only) | كود مرمي بس | أسبوع 3–7 | **Gate 0**: ≥5 دفعوا Proof Pilot، Meta BV، رأي قانوني، spikes ناجحة |
| **P1** | استرجاع end-to-end بـholdout وتقرير ربح | أيوه (الأساس كله) | 14–18 أسبوع واقعيًا | **Gate 1**: تجار جددوا بفلوس + صفر تسريب/opt-out متأخر/تحذير Meta |
| **P2** | Agent بيبيع جوه المحادثة من غير هلوسة | أيوه | 8–12 أسبوع | دقة سعر 100% على ≥300 حالة، ≤$0.03/محادثة |
| **P3** | Listing عام + فوترة + self-serve | أيوه | 8–12 أسبوع | 30–50 متجر بيدفع، MRR 15–30 ألف |
| P4–P6 | Zid، CRM lite، قنوات، خليج، المنصة الكاملة | — | — | **gate لكل Module**: ≥5–10 عملاء ملتزمين يدفعوا |

### P1 — Measured Recovery Pilot (≈18 pw بالـbuffer)

**المسار الحرج:** Meta App Review → E03 → E04 → E05 → E06 → أول بيانات holdout → 60 يوم live. عشان كده E01/E02/E15 بيتبنوا **بالتوازي** وإحنا مستنيين Meta.

| Sprint | الأسابيع | البناء | الـEpics |
|---|---|---|---|
| **S0** | W8 | **Setup**: repo `codex-revenue-os`، React starter kit (Teams)، CI (Pest + arch tests + isolation suite + lint يمنع `ml-/mr-/left-/text-left`)، **البراند كـtokens في Tailwind** (القسم 4)، نقل `docs/`، ADR-013/014/015 | — |
| **S1** | W9–10 | Workspace وAuth وTenancy (`tenant_id` + Global Scope)، Salla Adapter (OAuth Easy Mode، webhooks + `webhook_events`، reconciliation، refresh بـlock)، Security baseline (`audit_events`، تشفير الـtokens، PII redaction)، schema الـconsent، ADR-006 (region واتساب **قبل أول رقم**، قرار مينفعش يتغيّر) | E01، E02، E15، E04 |
| **S2** | W11–12 | WhatsApp onboarding (Embedded Signup v4، templates Marketing، MM API)، Consent ledger + opt-out بالعربي + quiet hours (22:00–09:00، رمضان 01:00–12:00)، `scheduled_actions` + الـrecovery workflow، الهامش لكل فئة | E03، E04، E05، E08 |
| **S3** | W13–14 | محرك سياسات الخصم + approvals، **Holdout + Cost ledger**، التقرير **يدوي** (SQL + template)، metering. **أول 2–3 تجار live** | E05، E06، E07 (يدوي)، E13a |
| **S4** | W15–16 | Handoff inbox lite (queue/assign/notes/status)، Filament admin (صحة التكاملات، DLQ، kill switch لكل tenant) | E12a، E14 |
| **S5** | W17–18 | صفحة Incremental Profit Report في المنتج، فوترة يدوية بروابط Moyasar/Tap | E07، E13a |
| **S6** | W19+ | Gate review | — |

**لو الوقت ضاق، التأجيل بالترتيب ده:** (1) صفحة التقرير تفضل يدوي، (2) الـinbox lite، (3) الأدمن يقتصر على الصحة والـDLQ.
**مينفعش يتأجل أبدًا:** consent/opt-out، isolation suite، `webhook_events`/reconciliation، holdout وcost ledger، محرك الخصم.

**تعديلات مقترحة على P1 من المراجعة المستقلة [اقتراح، قرارك]:**
1. **قبل أول تقرير:** نعيد تعريف المقياس لـ"فرق متوسط **المساهمة** لكل عميل مخصص للتجربة" (بما فيهم اللي ماشتروش، ومخصوم منها المرتجعات والإلغاء)، مش "فرق معدل التحويل × متوسط الطلب" ([15](15-independent-plan-review.md) #1).
2. **نفصل Gate 1 لـ3 بوابات:** جاهزية التشغيل، كفاية البيانات، التجديد المدفوع. والـ90 يوم بتاعة الـpilot تتحسب من **تاريخ التفعيل الفعلي** (#5).
3. **نحدد التجربة بتقارن بإيه:** CODEX مقابل حل التاجر الحالي، ولا CODEX مقابل ولا حاجة (#3).
4. **الضمان** يبقى على التزامات قابلة للتحقق (تفعيل، تقارير، تشغيل سليم)، مش على تقدير مجمّع فيه noise (#11).
5. التقرير يعرض 3 حالات بس: **مفيد / ضار / غير حاسم**. و"غير حاسم" مش معناه فشل.
