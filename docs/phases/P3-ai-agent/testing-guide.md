# دليل اختبار P3 (الـAI Sales Agent)

> لمين: المؤسس، وأي حد بيراجع الـagent قبل أول تاجر.
> الحالة: على branch `feat/P3-ai-agent` (2026-10-25). **مفيش key مدفوع اتستخدم**: كل حاجة شغالة بموديل fake في الـtests، و`CODEX_AI_PROVIDER=demo` محليًا.
> القرارات والتصميم في [ADR-007](../../adr/ADR-007-ai-orchestration.md) و[ADR-008](../../adr/ADR-008-pii-and-llm.md).

## 1. شغّله محليًا

نفس خطوات P2 ([دليل P2](../P2-frontend/testing-guide.md) §1)، وزوّد في `.env`:

```bash
CODEX_AI_PROVIDER=demo              # ردود جاهزة من غير key (مرفوض في production)
CODEX_EMBEDDINGS_ENABLED=false      # البحث بالنص بس، من غير Voyage
CODEX_PRICE_MAX_AGE_MINUTES=100000  # المتجر التجريبي مفيهوش sync من سلة، فالأسعار "قديمة" بعد 15 دقيقة. محلي بس
```

> `CODEX_AI_PROVIDER` مش مكتوب في `.env.example`، والافتراضي `anthropic`. من غير key، كل رسالة هتتحوّل لإنسان (`provider_unavailable`).

بعدين:

```bash
docker compose up -d pgsql
php artisan migrate
php artisan db:seed --class=DemoStoreSeeder   # متجر عطور صغير + FAQ/شحن/استرجاع + الـagent في Assisted
composer dev                                  # API على :8000 والتطبيق على :3001
```

> `DemoStoreSeeder` محلي بس. **عمره ما يشتغل على production.**

اللي الـseeder بيعمله للـP3: 4 منتجات (عود كمبودي ملكي، مسك أبيض، ماء ورد طائفي **خلصان**، بخور المجالس)، ونصوص الشحن والاسترجاع والـFAQ، والعميل التجريبي `0551234567` عنده consent، والـagent متشغّل **Assisted**.

## 2. ابعت رسالة كأنك عميل

```bash
php artisan codex:demo-message "بكم العود الكمبودي؟"
```

الأمر ده بيعدّي **على مسار الـwebhook الحقيقي** بتاع Meta (opt-out، المحادثة، الـagent)، والـqueue بيشتغل sync فالنتيجة بتبقى جاهزة لما الأمر يخلص. اختيارات: `--phone=05...` لرقم تاني، و`--team=<slug>` لـworkspace تاني. مرفوض في production.

**بـ`demo`:** الموديل التجريبي بيعمل `search_products` وبيكتب نفس الرد الجاهز لأي سؤال («رد تجريبي من الذكاء الاصطناعي: …»)، **من غير أرقام**. ده كفاية تجرّب الـflow كله (مسودة، موافقة، takeover)، بس **مش بيقيس جودة الردود**. الجودة محتاجة key حقيقي (§5).

## 3. اللي تجرّبه (حوالي 10 دقايق)

ادخل بـ`owner@demo.test` / `password`. الروابط تحت `/ar/t/<slug>/...`.

| # | فين | اعمل إيه | المفروض تشوف |
|---|---|---|---|
| 1 | Terminal | `php artisan codex:demo-message "بكم العود الكمبودي؟"` | `Delivered to …` |
| 2 | **المسودات** (`/drafts`) | افتح الصفحة | مسودة واحدة مستنية، بالرد التجريبي |
| 3 | المسودات | عدّل النص واضغط موافقة | الإرسال **هيفشل** (`failed`): token واتساب التجريبي مزيف. ده متوقع (§5) |
| 4 | Terminal | `php artisan codex:demo-message "فيه خصم على العود؟"` | — |
| 5 | **المحادثات** → المحادثة | افتح لوحة الـAI | **مفيش مسودة**. المحادثة اتحوّلت لإنسان بسبب «طلب خصم»، قبل ما الموديل يتنادى أصلًا |
| 6 | المحادثة → لوحة الـAI | شوف السجل (log) | لكل رسالة: الحالة (مسودة / handoff / skipped)، والسبب، والـtools اللي اتنادت. **مفيش نص رسايل في السجل** |
| 7 | المحادثة | اضغط **takeover** (استلام المحادثة) | الـAI متوقف للمحادثة دي، وأي مسودة مستنية بتتلغي |
| 8 | Terminal | ابعت 2–3 رسايل بـ`codex:demo-message` | **ولا مسودة جديدة** (الـruns بتتسجّل `skipped: paused`) |
| 9 | المحادثة | اضغط **رجّعها للـAI** (hand back) | الرسالة الجاية بتعمل مسودة تاني. الـtakeover والـhand back متسجّلين في `audit_events` |
| 10 | **معلومات المتجر** (`/knowledge`) | عدّل نص الشحن واحفظ | اتحفظ. ده النص الوحيد اللي الـagent بيجاوب منه في الشحن |
| 11 | **إعدادات الـAI** (`/ai`) | شوف الوضع والسقف | الوضع Assisted. Scoped Autonomous **مقفول** ومكتوب ليه (flag الأدمن، 28 يوم، موافقة مكتوبة). السقف $5 |
| 12 | إعدادات الـAI | حاول تحط السقف 10 | مرفوض: تقدر **تنزّله بس** (من $0.10 لـ$5) |
| 13 | اخرج وادخل بـ`agent@demo.test` | — | المسودات والمحادثات ظاهرين. معلومات المتجر وإعدادات الـAI مش ظاهرين. زرار إيقاف الـAI (kill switch) متاح في صفحة المحادثات |

رسايل تانية تجرّبها للـhandoff الحتمي: «ابي اكلم موظف» (طلب إنسان)، «طلبي ما وصل لليوم» (شكوى)، «عايز حاجة ارخص من كده» (خصم، مصري).

| الفحص | الأمر | بيغطي إيه |
|---|---|---|
| كل حاجة | `composer ci:check` | الـbackend (**326 test** أخضر في آخر تشغيل وقت الكتابة)، وPHPStan، وPint، والـweb lint/tsc، والـRTL |
| الـGolden set offline | `php artisan ai:eval` | 67 حالة بتتحكم offline (السكريبتات + الـhandoff الحتمي)، و13 live-only بتظهر `·`. أي فشل في حالة سعر = blocking. التفاصيل في [golden-set-guide.md](golden-set-guide.md) |

## 5. اللي محتاج key حقيقي

| المطلوب | الـkey | من غيره |
|---|---|---|
| ردود حقيقية وقياس الجودة والتكلفة (`ai:eval --live`) | `ANTHROPIC_API_KEY` + `CODEX_AI_PROVIDER=anthropic` | ردود `demo` جاهزة، أو handoff لكل رسالة. **محتاج موافقة المؤسس قبل أي استخدام** |
| البحث بالمعنى (embeddings) | `VOYAGEAI_API_KEY` + `CODEX_EMBEDDINGS_ENABLED=true` | البحث بالنص بس (FTS + trigram)، وده شغال كويس لأسماء العطور والماركات |
| إرسال الرد فعلًا للعميل | رقم واتساب حقيقي وtoken من Meta | الموافقة على مسودة بتفشل (`failed`) لأن الـtoken التجريبي مزيف |
| أسعار حية من سلة | متجر سلة متربط (webhooks + sync كل 10 دقايق) | الأسعار من الـseeder، ولازم `CODEX_PRICE_MAX_AGE_MINUTES` كبير محليًا |

## 6. اللي مش متعمل، وليه

| البند | ليه |
|---|---|
| تشغيل live للـgolden set | مستني موافقة المؤسس على الـkeys. لحد دلوقتي الـexit criteria (100% سعر على ≥300، ≤$0.03، handoff ≤40%) **مش متقاسة** |
| ≥300 حالة | محتاج labeling بشري (AI/QA part-time) |
| اسم يكتبه العميل بنفسه مش بيتخبّى | أسماء الفريق بتتخبّى، واسم العميل مش متاح من سلة ([ADR-008](../../adr/ADR-008-pii-and-llm.md) §1) |
| ≥4 أسابيع Assisted | بيبدأ مع أول تاجر بعد Gate 0 |
