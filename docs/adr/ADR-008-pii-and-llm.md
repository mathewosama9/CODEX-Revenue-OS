# ADR-008: البيانات الشخصية (PII) مع الـLLM

- **الحالة:** الجزء التقني **Implemented** (P3، 2026-10-25). الجزء القانوني **Open**، مستني رأي المستشار القانوني.
- **صاحب القرار:** المؤسس + المستشار القانوني
- **المرجع:** [14](../blueprint/14-key-decisions.md) D-T10، و[09](../blueprint/09-technical-architecture.md) §9.11، وUS-E10-04، وADR-015 (الـlogs).
- **مرتبط بـ:** [ADR-007](ADR-007-ai-orchestration.md).

> **تنبيه:** أي جملة قانونية هنا **[افتراض]** لحد ما المستشار القانوني يراجعها. إحنا مش محامين، والـADR ده بيوصف اللي عملناه تقنيًا، والأسئلة اللي محتاجين ردها.

## القرار

**الموديل مبيشوفش هوية العميل.** البيانات الشخصية بتتبدّل بـtokens قبل النداء، وبترجع في الرد بعده. ومفيش نص محادثة بيتخزن في أي مكان جديد غير مشفّر.

## 1. الـPseudonymization (`app/Modules/AiGateway/Pseudonymizer.php`)

| النوع | إزاي بيتلقط | الـtoken |
|---|---|---|
| إيميل | regex للإيميل | `[EMAIL_A]` |
| تليفون، أو أي **9 أرقام أو أكتر ورا بعض** (كروت، IBAN) | بعد تحويل الأرقام العربية/الهندية للاتيني، ومع المسافات والشُرط والنقط اللي الناس بتكتبها بين الأرقام، و`+` | `[PHONE_A]` |
| أسماء معروفة (`AiRequest::$knownNames`) | كلمة كاملة، من غير حساسية لحالة الحروف | `[NAME_A]` |

- الـtokens **حروف مش أرقام** (`A`، `B`، ...، `AA`) عشان الـvalidator ميفتكرهاش سعر، والـvalidator بيتجاهلها صراحةً.
- نفس القيمة = نفس الـtoken في نفس النداء.
- بعد الرد: `restore()` بيرجّع القيم الأصلية، **بعد** ما الـvalidator يقرا كلام الموديل.
- الـsystem prompt بيقول للموديل يسيب الـtokens زي ما هي.

**الإثبات:** `tests/Feature/AiGateway/AiGatewayTest.php` → *"sends zero personal data to the model across 1,000 calls"*: 1,000 نداء بأسماء سعودية من Faker، وأرقام بـ4 أشكال (محلي، `+966` بمسافات، أرقام هندية، شُرط)، وإيميلات. الـtest بيفحص الـpayload كله اللي اتبعت للموديل (instructions + messages + prompt) ويطلب **صفر تسريب**، وإن كل نداء اتسجّل فيه ≥3 قيم اتخبّت.

### حدود معروفة (مهم)

| الحد | الأثر | التصنيف |
|---|---|---|
| **`SalesAgent` بيبعت أسماء أعضاء الفريق بس كـ`knownNames`** (ككلمات كاملة) | سلة مبتديناش اسم العميل، فاسم يكتبه العميل بنفسه **بيوصل للموديل** | فجوة مفتوحة: كشف أسماء (NER) أو اسم العميل من سلة لو اتوفر، أو قبولها قانونيًا |
| أسماء مش معروفة لينا (اسم حد تاني، عنوان) | بتعدّي | [افتراض] الخطر قليل في محادثات بيع، بس العناوين ممكن تظهر في سؤال الشحن |
| رقم أقل من 9 أرقام | بيعدّي (مقصود: الأسعار والكميات لازم توصل) | قرار تصميم |
| مطابقة الاسم كنص | ممكن تخبّي كلمة عادية لو اسم العميل كلمة شائعة (مثلًا "ورد") | [افتراض] أثر بسيط على جودة الرد |

## 2. اللي بيتخزن، واللي لأ

| المكان | بيتخزن إيه | مبيتخزنش |
|---|---|---|
| `ai_calls` | metadata بس: الغرض، `conversation_ref` (`conv:<id>`)، المزوّد، الموديل، الحالة، tokens، التكلفة، latency، عدد الـtools، عدد القيم المخبّية، اسم class الخطأ (≤120 حرف) | **الـprompt والرد** |
| `agent_runs.trace` | أسماء الـtools، و`product_id`، و`topic`، والأرقام اللي الـvalidator منعها | **أي نص رسالة** (فيه test: *"shows the agent log … without message text in the trace"*) |
| `reply_drafts.body` و`final_body` | نص رد الـAI | **مشفّر at rest** (`encrypted` cast) |
| `conversations.phone` | الرقم E.164 عشان نبعت الرد المعتمد | **مشفّر** (`encrypted` cast) |
| `eval_runs` | نتايج الـgolden set (حالات مكتوبة مننا) | مفيش بيانات تجار |
| الـjobs (`RespondToCustomer`) | `tenantId` و`conversationId` و`inboundMessageId` بس | مفيش نص ولا رقم في الـqueue payload |
| الـlogs | اسم class الخطأ واسم الـtool | مفيش نص رسالة. والـRedactor من P1 (ADR-015) شغال |

## 3. الـtests مبتطلعش برّه

`tests/TestCase.php` فيه `Http::preventStrayRequests()`: أي HTTP request حقيقي في الـtests بيفشل. والـLLM متختبر بـ`GatewayAgent::fake()` (`App\Modules\AiGateway\Testing\FakeLlm`). **مفيش key مدفوع اتستخدم، ومفيش بيانات اتبعتت لأي مزوّد.**

## 5. أسئلة للمستشار القانوني

1. هل نداء LLM لحظي لمزوّد برّه المملكة (US أو global)، بنص مخبّي فيه الاسم والرقم والإيميل، يُعتبر **نقل بيانات شخصية برّه المملكة** تحت PDPL ولائحة النقل؟
2. لو أيوه: إيه الأساس القانوني المناسب (موافقة، ضرورة تنفيذ عقد، ضمانات تعاقدية)؟ وهل SCCs أو بند في الـDPA كفاية؟
3. هل الـpseudonymization اللي عملناه (والمفتاح عندنا) بيقلّل التصنيف أو المتطلبات؟ ولا البيانات لسه شخصية بالكامل؟
4. هل لازم نذكر Anthropic وVoyage بالاسم في سياسة الخصوصية اللي العميل النهائي بيشوفها؟ ولا قائمة sub-processors عند التاجر كفاية؟
5. هل عقد ZDR مع Anthropic شرط قبل أول pilot، ولا كفاية شروط الـAPI العادية (no training)؟
6. هل محتاجين موافقة العميل صراحةً قبل ما الـAI يرد عليه (حتى في Assisted، والرد بيعدّي على موظف)؟ وهل لازم نقول له إن الرد "بمساعدة AI"؟
7. هل نقدر نستخدم محادثات حقيقية من أول التجار (بعد إخفاء الهوية) في الـgolden set **للاختبار بس**؟ وإيه الصيغة اللي لازم تبقى في الـDPA؟
8. مدة الاحتفاظ بـ`reply_drafts` (نص مشفّر) و`ai_calls` (metadata): كام؟
9. لو العميل طلب حذف بياناته: هل المسودات المشفّرة لازم تتمسح؟ (طلبات البيانات من P1 لازم تغطيها.)
10. Meta: هل سياسة "AI chatbots" بتنطبق علينا كمنصة تجارة، طالما الـagent جوه كتالوج التاجر وبيرفض الأسئلة العامة؟

## 6. اللي فاضل تقنيًا

- كشف اسم العميل لما يكتبه بنفسه (الفجوة في §1).
- اختبار PII أسبوعي على production (06 B.5.1) بعد أول pilot.
- مراجعة الـpayload اللي رايح لـVoyage.
