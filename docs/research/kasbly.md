## 1. الخدمات والمنتجات

1. **كسبلي للتسويق (Kasbly Marketing)** في `/ar/products/create`. ينتج المحتوى بـ AI (صور منتجات، فيديوهات UGC، نصوص) ويجدول النشر. **[مؤكدة]** https://kasbly.com/ar/products/create (2026-10-21)

4. يصف الموقع نفسه بأنه "موظف AI يغني عن فريق تسويق ومبيعات". هذا ادعاء تسويقي. **[مؤكدة]** https://kasbly.com/ar (2026-10-21)

## 4. تجربة المستخدم (من المتاح علنًا)

- تسجيل ذاتي (self-serve) مجاني بدون بطاقة ائتمان عبر `app.kasbly.com/sign-up?lang=ar`. **[مؤكدة]** https://kasbly.com/ar (2026-10-21)
- يدّعي الموقع أن الإعداد يستغرق "5 دقائق". مقال في المدوّنة يقول "حوالي ظهيرة واحدة" بدون مطوّر. **[مؤكدة]** https://kasbly.com/ar و https://kasbly.com/ar/blog/connect-autopilot-with-your-tools (2026-10-21). الرقمان متناقضان.
- خطوات الـ onboarding في التوثيق: ربط قناة، ثم إعداد الوكيل، ثم إضافة جهات الاتصال، ثم المتابعة من الـ inbox. **[مؤكدة]** https://docs.kasbly.com/ar/ (2026-10-21)
- يُضبط الوكيل من "خريطة إعداد" (configuration map) تربط القنوات والأدوات والمعرفة. **[مؤكدة]** https://docs.kasbly.com/ar/ai-agent/overview/ (2026-10-21)
- ربط واتساب يتم يدويًا: تدخل Phone number ID وWABA ID وAccess token، ولا يوجد Embedded Signup موثّق. **[مؤكدة]** https://docs.kasbly.com/ar/channels/whatsapp/ (2026-10-21). **[افتراض]** هذا احتكاك كبير للتاجر غير التقني.
- الموقع والتوثيق متاحان بالعربية والإنجليزية. **[مؤكدة]**. أما جودة الـ RTL داخل لوحة التحكم فغير مؤكدة، لأني لم أدخل التطبيق.
- يذكر الموقع أن "أشخاصًا حقيقيين" يساعدون في ربط القنوات وتدريب الوكيل، وهذا يعني onboarding بمساعدة بشرية. **[مؤكدة]** https://kasbly.com/ar/about (2026-10-21)

## 9. نقاط الضعف والفرص

1. **استرجاع السلات المتروكة الحقيقي غير موجود عندهم.** لا يقرأ سلات سلة أو زد، ويكتفي بروابط الدفع المرسلة داخل المحادثة. **[مؤكدة]** https://kasbly.com/ar/blog/salla-zid-whatsapp-integration. **فرصة [اقتراح]:** هذه نقطة دخول CODEX الأساسية: webhooks السلات المتروكة من سلة مع تقييم (scoring) وقرارات واعية بالربح.
2. **المدفوعات عبر Stripe فقط.** Stripe غير متاح مباشرة للتجار السعوديين بشكل واسع **[افتراض]**، ولا يوجد ذكر لمدى أو Tap أو Moyasar أو Tabby أو Tamara، ولا لتأكيد طلبات الدفع عند الاستلام (COD). **فرصة [اقتراح]:** روابط دفع محلية وتأكيد COD عبر واتساب.
3. **تكامل المتاجر سطحي أو غير موثّق.** لا توجد صفحة توثيق لسلة أو زد، ولا تطبيق في متجر سلة **[مؤكدة]** (بحث 404)، وهناك تناقض حول إنشاء الطلبات. **فرصة [اقتراح]:** تطبيق رسمي في متجر سلة مع OAuth وتثبيت بنقرة.
4. **ربط واتساب يدوي** بالـ token وWABA ID بدون Embedded Signup. **[مؤكدة]**. **فرصة [اقتراح]:** Embedded Signup بصفة Tech Provider أو عبر BSP.
5. **قياس الأثر ضعيف:** Revenue وattribution وROI موجودة، لكن بدون نموذج attribution معلن ولا control groups ولا مقاييس ربح أو هامش. **[مؤكدة]** https://docs.kasbly.com/ar/analytics/revenue/
6. **الثقة والامتثال:** كيان أمريكي، ورقم أمريكي، ولا ذكر لـ PDPL أو توطين البيانات، ولا لإدارة opt-out موثّقة. **[مؤكدة]** https://kasbly.com/ar/privacy و https://docs.kasbly.com/ar/settings/compliance/
7. **لا يوجد إثبات اجتماعي:** لا عملاء ولا case studies، وكل الأرقام "illustrative". **[مؤكدة]**
8. **تسعير غير معروف** بعد البيتا. هذا يخلق خطر تغيّر السعر عند التاجر. **[افتراض]**
9. **منتج واسع جدًا لفريق صغير** (تسويق ومبيعات ومكالمات وMCP و10 قنوات وأكثر)، والتوثيق سطحي في صفحات كثيرة. **[افتراض]** هذا يعني عمقًا ضعيفًا في كل ميزة على حدة.
10. **Handoff يدوي** بدون قواعد تصعيد تلقائية موثّقة. **[مؤكدة]** https://docs.kasbly.com/ar/inbox/handoff/

## 10. ميزات يمكن أن نتعلم منها **[اقتراح]**

- **Shadow mode، ثم إطلاق مرحلي، ثم مستويات استقلالية** للوكيل (من الإشراف إلى الاستقلال الكامل).
- **سقف خصم يحدده التاجر**، وقائمة "إجراءات تحتاج موافقة".
- **سجل إصدارات للوكيل** مع اقتراحات تحسين ونتائج كل تغيير.
- **Knowledge gaps report** وQuality review checklists.
- **حدود تنبيه وإيقاف للإنفاق** وتقرير تكلفة AI، وهذا مهم مع رسوم Meta.
- **MCP server** للقراءة وإنشاء المسودات فقط، مع audit لكل إجراء.
- **Lead scoring بـ decay.**
- **محتوى SEO عربي** يستهدف "سلة/زد + واتساب" و"السلات المتروكة".
- اختبار "10 رسائل صعبة" كأداة بيع تثبت جودة اللهجة.

## 11. ميزات يمكن أن نبنيها أفضل **[اقتراح]**

- **استرجاع السلات من المتجر نفسه** (Salla webhooks) بدل الاكتفاء بروابط المحادثة، مع تقييم احتمالية الشراء وتوقيت ذكي وساعات هادئة.
- **قرار خصم واعٍ بالربح:** خصم حسب الهامش والاحتمال، لا مجرد سقف ثابت.
- **Incrementality حقيقية:** holdout/control groups وتقرير "الإيراد الإضافي الصافي"، مقابل attribution غير معلنة المنهجية عندهم.
- **إنشاء السلة أو الطلب فعليًا** داخل سلة مع رابط دفع محلي (مدى وApple Pay وTabby وTamara).
- **تأكيد COD** عبر قوالب واتساب.
- **Embedded Signup لواتساب** وتطبيق رسمي في متجر سلة.
- **إدارة consent وopt-out** صريحة: كلمات STOP، وقوائم منع، وسجل موافقات، والتوافق مع PDPL.
- **Handoff تلقائي** بقواعد (نية شراء عالية، أو غضب العميل، أو قيمة سلة كبيرة) مع SLA.
- **دعم اللهجات بأدلة:** مجموعة تقييم منشورة، ودعم الرسائل الصوتية.
